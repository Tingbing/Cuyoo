## Implemented semantics

- Ordinary human entrants start unassigned. Waiting-room Team A and Team B cards show names and `count/capacity`; either card is a keyboard-accessible button. The server action derives the player from the authenticated session, checks current occupancy, waiting phase, team identity and capacity, and commits with the existing room-version compare-and-swap. Same-team retries are idempotent; a rejected full-team switch preserves the original team.
- Capacity is always `N/2`. Start requires the verified host, a waiting room, exactly four or six occupied seats, every participant connected, no unassigned or duplicate participant, and exactly balanced teams. The backend rechecks the same gate atomically. Start maps each chosen team into deterministic join order and then canonical `A-B-A-B[-A-B]` seats before random dealer selection. Cutter and initial leader are derived from the final seats. Active replacement keeps the fixed seat/team/cards/position; rematch keeps the fixed allocation.
- Test rooms begin unassigned. When the human chooses either team, only bot memberships are rebalanced atomically to fill both teams. Ordinary rooms never receive automatic rebalancing.
- Migration `0002_quick_magus.sql` adds server-owned `last_human_activity_at`, `expires_at`, and `activity_version`. Existing rows backfill from `state.created`, falling back to persisted `rooms.updated`; migration time, bots, cleanup, polling, presence, and derived writes never count as human use. Accepted create, join/resume, team choice, Start, cut/pass/trump/play, result dismissal, lead request, rematch, and other legitimate human actions extend expiry by exactly 21,600,000ms. Rejected or replayed duplicate actions do not.
- At `serverNow >= expiresAt`, direct access, resume, join, and actions fail; lobby filtering removes the row immediately. Bounded request-side cleanup rechecks the stored deadline before deleting room state and clearing live membership/connection state. This works on the existing free hosting without a paid cron. Cleanup and normal writes use deadline/version guards, so stale cleanup cannot delete a renewed table and late actions cannot revive one.
- `Lead trump` is a predefined, advisory first-lead signal. Only current teammates of the authoritative initial leader, excluding the leader, can send once per occupant epoch/hand after trump is selected and before any card is played. The target seat is server-derived. Only the current occupant projection for that leader seat contains sender names; public/opponent projections do not contain the notices. The first card, new hand/redeal, reset, expiry, or match completion clears them. Replacement of the leader seat receives the still-current private notice. Bots neither send nor alter strategy in response.
- A private maintenance-only three-phase reset path uses a secret environment binding and same-origin POST. `begin` guards room-changing writes and reports counts; `execute` records private D1 recovery snapshots, clears connections/memberships, and deletes all rooms; `finish` requires an authoritative zero count before restoring availability. It is not a startup wipe, migration wipe, or public endpoint.
